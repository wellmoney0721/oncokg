## Code blockers

**M32-B1 — comparing an echoed linker window does not prove a stored-name match.** At `src/app.py:111-115`, `_sig(input)` is compared with `_sig(matched_text)`. But `src/query.py:872-877` supplies the candidate input window after looking it up through the lossy canonical key (`src/textrules.py:340-347`). This proves input-span coverage, not equality to an actual stored alias. `_plain` permits characters the dictionary discards.

`trastu+zumab`, `trastu$zumab`, and `trastu=zumab` all draw **CHEMBL1201585 TRASTUZUMAB**. So do `trastuzumabß`, `trastuzumabø`, `trastuzumabæ`, `trastuzumabł`, `trastuzumabð`, and `trastuzumabı`. The significant extra symbol/letter is absent from every stored alias of the drawn drug. The root independently checked full stored aliases/live nodes for `trastu+zumab` and `trastuzumabß`; neither has a matching name. This violates P32-1 regardless of whether the altered text denotes a real marketed product. [HTTP and alias proof](root_additional_http.json), [broader variants](attacks/http_identity.json), [independent sanity assertions](attacks/sanity_assertions.json).

**M32-B2 — company fallback bypasses significant-name equality.** `src/app.py:120-122` accepts a canonical company key whenever `_plain(text)` is true. It never compares the input with a stored name/key retaining significant symbols. **`AstraZeneca +` -> ORG:astrazeneca**, **`Merck + Co` -> ORG:merckco**, and **`Pfizer$`/`Pfi+zer` -> ORG:pfizer**. `Roche $` draws only the company, whereas `Roche` correctly offers the folic-acid/company choice. This is an independent acceptance path even when the linker-window equality fails. The requested `_latin` implementation is absent from actual HEAD; the reviewed implementation is `_plain`. `Merck & Co` itself is a valid stored-label control, not a reported counterexample. [Independent HTTP](root_http.json), [extra company controls](attacks/http_identity.json).

**M32-B3 — shared-name collection uses inconsistent equivalence rules.** P32-3 requires a reader choice for several live nodes sharing one name, ignoring case/spacing/punctuation. The map's `_label_key` retains punctuation, target fallback is literal lowercase, and drug candidates inherit P32-5's question-only preferred-name selection (`src/app.py:111-125,242-244`; `src/query.py:742-747`). A sweep of155 ambiguous spellings finds six that draw rather than choose:

| Exact input | Live candidates sharing the significant name | Incorrect automatic result |
|---|---|---|
| `ABT-510` / `ABT 510` | CHEMBL386115 and CHEMBL262489 | Each spelling draws its own preferred-name node |
| `MAGE-A3` | CHEMBL2108705 ASTUPROTIMUT-R and ENSG00000221867 MAGEA3 | Draws the drug; `MAGEA3` correctly chooses |
| `ctla-4` | CHEMBL1789844 IPILIMUMAB and ENSG00000163599 CTLA4 | Draws the drug; `CTLA4` correctly chooses |
| `FLUDEOXYGLUCOSE F 18` / `FLUDEOXYGLUCOSE-F18` | CHEMBL2030434 and CHEMBL497613 | Each spelling draws its own preferred-name node |

All candidates were independently checked live in SQL. MAGE-A3 and ctla-4 demonstrate the failure without relying on the drug-preferred-name exception. Duplicate source names are data facts; automatically selecting one is a map-code violation. P32-5 allows preferred-name selection in question linking, but does not waive the map's choice rule. [Complete sweep](attacks/shared_signatures.json), [independent HTTP/SQL confirmation](root_additional_http.json).

**M32-B4 — a supposedly ignored trademark changes identity.** NFKC expands `™` into letters `TM` before `_sig` removes trademark characters (`src/app.py:237-239`). **`Tarceva`/`Tarceva®` draw CHEMBL1079742 ERLOTINIB HYDROCHLORIDE; `Tarceva™` draws CHEMBL553 ERLOTINIB.** The latter uses a separate stored AACT alias `tarcevatm`. That alias explains the lookup but cannot authorize interpreting a literal ignored trademark as significant letters under P32-1. `trastuzumab™` and `AstraZeneca™` instead lose recall; those are should-fix manifestations, not additional wrong-node cases. [Root HTTP](root_http.json), [interpretation checks](attacks/sanity_assertions.json).

A repair needs to establish identity against actual stored names, collect **all live candidates under one consistent name-equivalence rule**, and only then draw or choose. Comparing text with its own extracted window or checking a character class cannot establish this. Trademark handling must precede compatibility expansion. These are review conclusions, not an implemented patch.
