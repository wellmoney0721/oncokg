# OncoKG — 임상시험 자유 텍스트에서 약물 지식그래프로

공개 데이터만으로 만든 비소세포폐암(NSCLC) 영역 데이터 파이프라인입니다. 임상시험 등록부의
지저분한 자유 텍스트를 표준 식별자로 정규화하고, 출처와 변경이력을 가진 지식그래프를 구축하고,
그 위에서 근거 기반으로 답하며, **무엇을 틀렸는지 함께 보고합니다.**

핵심은 그래프 자체가 아니라, 정제된 참조 어휘와 사람이 실제로 입력한 텍스트 사이의 간극,
그리고 **없는 사실을 지어내지 않으면서** 그 간극을 건너는 방법입니다.

전체 기술 문서는 [README.md](README.md)에 있습니다. 아래는 요약입니다.

## 문제

임상시험 3,000건 안에서 약 1,000종의 분자가 **2,742개의 서로 다른 문자열**로 등장하고,
하나의 질환이 **2,175개의 표기**로 나타납니다.

| 유형 | 실제 사례 |
| --- | --- |
| 용량·투여경로 노이즈 | `Pembrolizumab 100 mg I.V single dose` |
| 염·제형 | `Anlotinib hydrochloride capsule` |
| 상품명·개발코드 | `Avastin`, `ZD6474 (ZACTIMA)`, `OSI-774` |
| 구분자 없는 병용 | `Cisplatin Docetaxel Gefitinib Pemetrexed` |
| 위약 | `Placebo Erlotinib 150/100mg` vs `placebo plus docetaxel` |
| 약물이 아닌 계열어 | `Platinum Based Chemotherapy` |
| 같은 분자, 다른 제품 | `Bevacizumab Biosimilar HLX04` |
| 방사성 추적자 | `[18F]F-AraG PET imaging` |

## 측정 결과 — 분모를 둘 다 적습니다

튜닝에 쓴 데이터로 잰 수치는 측정이 아니므로, **서로 겹치지 않는 세 개의 수작업 채점 샘플**로
측정했습니다.

**헤드라인은 88.7%입니다** — 홀드아웃 테스트에서 수용된 매칭 115건 중 102건이 맞았습니다
(Wilson 81.6–93.3). 그 샘플을 떼어 둘 당시의 파이프라인을 채점한 값입니다. 처음엔 91.3%였고,
2차 독립 감사가 관대하게 채점된 홀드아웃 라벨 2건을 찾아 89.6%, 3차가 1건을 더 찾아 88.7%가
됐습니다. 매번 숫자가 내려갔고, 방어할 수 있는 쪽은 이 숫자입니다.

| 샘플 | 행 수 | 라벨 당시 수용 행 | **라벨 당시 원시 정밀도** |
| --- | --- | --- | --- |
| 개발셋 | 214 | 137 | 90.5% (84.4–94.4) |
| **홀드아웃 테스트** | **172** | **115** | **88.7% (81.6–93.3)** |
| 수정 후 확인 | 58 | 38 | 92.1% (79.2–97.3) |

**수리된 파이프라인의 홀드아웃 수치는 없고, 공표하지도 않습니다.** 세 차례 감사가 테스트 샘플로
결함을 찾았고, 그 수리로 172행 중 26행의 해석이 바뀌었습니다. 이 행들은 *낡은 라벨*이라
`src/evaluate.py`가 판정을 지어내지 않고 따로 빼서 재라벨링 목록으로 남깁니다. 남은 행은 98건 중
98건이 맞지만, 오류는 전부 낡은 행 쪽에 있었으므로 남은 행은 수리가 건드리지 않은 행일 뿐입니다.
평가 JSON에는 이 남은 행에 대한 층화 추정치와 구간 두 개(`accepted_precision`)가 아직 들어 있지만,
살아남은 행만 골라 계산한 값이라 여기서는 정밀도로 싣지 않습니다. **수리된 파이프라인을 재려면
작성자가 아닌 사람이 라벨링한 새 샘플이 필요합니다.**

**샘플 크기는 정밀도의 분모가 아닙니다.** 매칭을 주장한 행만 맞고 틀릴 수 있고, 나머지는 거절이므로
따로 채점합니다. 홀드아웃 172행 중 라벨 당시 매칭을 주장한 것은 115행입니다. 172를 분모로 인용하면
근거를 부풀리는 것이고, **이 문서의 이전 판이 정확히 그렇게 쓰여 있었습니다.**

**헤드라인이 층화가 아니라 원시 수치인 이유.** 샘플을 계층별 불균등 쿼터로 뽑았으므로 원리상
층화 추정이 맞는 추정량이지만, 그러려면 라벨 당시의 계층별 모집단 크기가 필요한데 저장해 두지
않았습니다. 오늘의 모집단으로 예전 라벨을 가중하면 두 파이프라인을 한 숫자로 섞게 되고, 첫 판이
그렇게 했습니다. 그 판은 층화 평균에 정규근사 구간을 붙여 `99.1% [98.4, 99.8]`을 공표했는데,
가중치의 88%가 100% 계층에 있어 분산 항이 0이 되어 구간이 무너졌습니다.

약물성 문자열 커버리지는 **78.0%** (6,329 중 4,936)입니다. 정밀도와 커버리지를 분리해 보고하는
이유는, 커버리지는 임계값만 낮추면 언제든 살 수 있고 하나의 숫자로 합치면 그 거래가 가려지기
때문입니다.

헤드라인만큼 중요한 두 숫자:

- **44.4%** (개발셋 중 지금도 유효한 9행 중 4행) — 파이프라인이 *검토로 보류한* 제안이 실제로
  맞았을 비율. 절반 아래라는 것이 자동 임계값이 과하게 낮지 않다는 증거지만, 9행이라 약한
  증거입니다.
- **100%** (8/8, Wilson 67.6–100) — 홀드아웃 샘플에서의 위약 가드. 개발셋에서 병용 arm을
  과차단하던 문제를 고친 뒤 검증된 수치입니다.

## 독립 검증이 찾아낸 것

세 샘플의 모든 라벨은 **매칭 규칙을 작성한 본인이** 붙인 것입니다. 한계 항목에 그렇게 적어두는
것과 실제로 검증하는 것은 다른 일이므로, 반박하라는 지시와 함께 독립 검토자에게 세 번 넘겼고, 세 번
다 반박당했습니다. 2·3차 보고서 원문은 `codex_report.txt`·`codex_report_round3.txt`, 증거는
`audit_evidence_20261103/`·`audit_evidence_round3/`에 있고, `CODEX_R2_VERDICT.md`·`CODEX_R3_VERDICT.md`에
지적마다 재현됐는지·일부 틀렸는지·검토자가 놓친 것까지 적었습니다.
아래는 전부 검토가 찾아낸 결함이고 이 저장소에는 수정이 반영되어 있습니다.

### 3차

**이 문서가 고쳤다고 적은 결함이 고쳐지지 않았습니다.** 2차 정리 때 남은 결함 목록에서 `adenovirus`
백신 항목을 "더 재현되지 않는다"며 뺐는데, 짧은 문자열만 확인했습니다. 샘플의 실제 문자열
`autologous dendritic cell-adenovirus CCL21 vaccine`은 50자이고 계열어 패턴의 수식어 상한이 40자여서,
여전히 TASADENOTUREV로 해석돼 살아 있는 엣지를 만들고 있었습니다. 상한을 90자로 올리고 맨
벡터 단어(`adenovirus`, `vaccinia`, `lentivirus`)를 계열어로 넣어 두 엣지를 모두 은퇴시켰습니다.

**질의층이 해석기의 거절 규칙을 우회했습니다.** 질문 단어를 동의어 색인에 바로 맞춰 보는 바람에
"Mvasi 시험은?"이 베바시주맙 시험 12건으로 답했습니다. 이제 별도 제품 이름은 어느 출처에서든 색인에
들어가지 않고, 질문에 별도 제품이 나오면 거절합니다.

**사명 변경이 여전히 소유 관계로 기록됐습니다.** `GSK`가 `GlaxoSmithKline`의 자회사가 됐고(자기 자신
검사가 모회사 표시 이름을 비교했음), Schering-Plough는 2009년 합병의 법적 존속 회사로서 Merck & Co.,
Inc.로 이름을 바꿨는데도 Merck & Co 아래에 있었습니다. 둘 다 이제 한 회사입니다.

**같은 제품 기준으로 라벨 4건이 더 관대했습니다** — `DN-101`(고용량 칼시트리올), `Genexol-PM`,
페길화 리포솜 독소루비신, `ABI-007`(Abraxane 개발코드). 홀드아웃 1건, 개발셋 2건, 수정 후 1건이고,
홀드아웃 수치는 89.6% → 88.7%가 됐습니다. 라벨 정정 대조가 성분 열을 보지 않던 것과 CSV 메모에
옛 사유가 남아 있던 것도 고쳤습니다.

**도메인 규칙 오류가 더 있었습니다.** `pembrolizumab-free regimen`이 펨브롤리주맙이 됐고(`free`를
FDA 접미사로 읽음), `[89Zr]pembrolizumab`의 동위원소가 사라졌고, 성장인자 바이오시밀러
(`filgrastim-sndz`)와 `Pazenir`가 원래 분자로 갔으며, 대문자 오리지널 접미사(`Cemiplimab-RWLC`)는
막혔습니다. 에스테르 검사가 동의어 조회보다 늦게 돌았고, 등록부 동의어만 검사해서 요법 약어
`ICE`가 이포스파미드가 됐고, `cisplatin + placebo to match pembrolizumab`에서 실제로 투여된 시스플라틴이
사라졌습니다. 근거 검사는 `aspirin`, `1e6`, `⅔`을 통과시켰습니다. 모두 회귀 시험이 붙었습니다.

### 2차

**골드 라벨 3건이 더 틀렸고(홀드아웃 2건, 수정 후 1건), 이번에도 관대한 방향이었습니다.** `CC-486`(경구 아자시티딘 — 허가
라벨이 주사제와 바꿔 쓰지 말라고 명시), `NanoPac`(나노입자 파클리탁셀), 수정 후 샘플의
`Nab-paclitaxel`을 AZACITIDINE·PACLITAXEL로 맞다고 채점했습니다. "별도 허가·대체 불가 제품은
다른 제품"이라는 기준은 1차에서 이미 세웠는데 이 셋이 그 기준을 어겼습니다. 1차 정정 하나는 사유가
틀려 있어(탁산이 병용 기반약일 뿐인 시험을 두 제형 비교 시험이라고 적음) 바로잡았습니다.
홀드아웃 수치는 91.3% → 89.6%로 내려갔습니다.

**관계 이름을 바꾼 것이 조회를 망가뜨렸습니다.** 그래프는 `SPONSORS_TRIAL_OF`로 바뀌었는데 질의층과
대시보드가 아직 `DEVELOPS`를 찾고 있어, "오시머티닙을 개발하는 회사는?"이 근거 0건으로 끝나고
대시보드의 회사 표가 비어 있었습니다. 이제 둘 다 새 이름을 읽고, 답변 줄마다 스폰서 분류와
"스폰서십은 개발 근거가 아니다"를 함께 적습니다.

**Merck 수정이 실제로는 유지되지 않았습니다.** `Merck & Co., Inc.`는 법인격 표기를 떼면 `merck`가
되고, `merckkgaa`가 `merck`로 시작하므로 역방향 접두 비교가 미국 회사를 독일 경쟁사의 자회사로
만들었습니다. 역방향 비교를 없앴습니다. 같은 검토가 `BeiGene`이 `BeOne Medicines`의 *자회사*로
기록된 것도 찾았습니다 — 사명 변경을 소유 관계로 저장한 것입니다. 이제 사명 변경과 같은 회사의
짧은 이름은 모회사를 찾기 전에 한 노드로 합치고, 실제로 다른 법인에만 `PARENT_OF`를 씁니다.
수식어 없는 `schering` 키가 바이엘 소속 Schering AG까지 잡던 것도 `scheringplough`로 고쳤습니다.

**빠진 시험의 파생 관계가 한 번 더 살아남았습니다.** 파생 스폰서십을 기본 엣지 은퇴보다 먼저
계산해서, 소스에서 빠진 시험이 여전히 그 계산에 들어갔습니다. 이제 기본 엣지를 먼저 정리하고,
어떤 소스도 언급하지 않는 노드는 은퇴로 표시해 살아 있는 수에서 뺍니다.

**근거 검증이 지어낸 내용을 통과시켰습니다.** 대문자 단어만 검사해서 `xyzabumab cures cancer.`가
통과했습니다. 숫자를 소수점에서 쪼개서, 근거가 `47.5%`일 때 지어낸 `47%`는 통과하고 정확한
`47.5%`는 거부했으며, 말로 쓴 숫자는 그냥 통과했습니다. 이제 약 이름 모양의 소문자 단어도 검사하고,
소수는 통째로 맞추고, 말로 쓴 숫자는 거부하며, 여전히 못 잡는 것을 함수 설명에 적었습니다.

**라벨 정정 점검이 항상 통과했습니다.** `--check`가 `PENDING`을 찍고는 "이미 다 반영됨"을 출력하며
0으로 끝났습니다. 이제 미반영 정정이 있으면 실패하고, 정정마다 행 번호뿐 아니라 원문 문자열과
해석 대상까지 맞는지 확인합니다.

**참조 어휘가 1차 측정보다 더 더러웠습니다.** 스냅샷의 동의어 9,316개 중 2,595개가 AACT에서
왔는데, AACT는 임상시험 개입 문자열을 분자에 연결한 것이라 그 arm에 함께 있던 것이 섞여 들어옵니다.
DEXAMETHASONE 아래 `tobramycin`, CISPLATIN 아래 `carboplatin`, PACLITAXEL 아래 `docetaxel`,
PREDNISONE 아래 `CHOP`, PEMBROLIZUMAB 아래 맨 단어 `mab` 같은 식입니다. 다른 성분·요법·여러 분자에
걸리는 약어·별도 제품을 가리키는 등록부 동의어를 지우는 큐레이션 규칙을 추가했습니다(2차 때
318개, 3차에서 별도 제품 이름을 따로 빼면서 지금 표에는 248개). 이 규칙은 거절 쪽으로 틀리며, 그 오류는 남은 결함에 적었습니다. 3차 감사가 3차 수리
전에 잰 비용은, 규칙을 끄면 수용 건수가 4,942 → 4,950(10건 잃고 2건 얻음)이 되는 정도였습니다.

**약사라면 바로 알아챌 도메인 규칙 오류가 여럿 있었습니다.** 바이오시밀러 상품명(`Mvasi`,
`Alymsys`, `Zirabev`)이 베바시주맙으로 해석됐습니다. FDA 네 글자 접미사를 전부 바이오시밀러로
봐서 `cemiplimab-rwlc` 같은 오리지널을 막았습니다. `liposomal doxorubicin`은 혼자일 때 막히고
`and cisplatin`을 붙이면 받아들여졌습니다(정리 과정이 가드가 찾는 단어를 지웠기 때문). 에스테르인
`prednisolone phosphate`를 염처럼 벗겼고, `No pembrolizumab`을 투여로 받아들였습니다. 병용 문자열의
괄호 코드가 엉뚱한 성분에 붙어 `AZD8205 and AZD5305 (saruparib)`에서 AZD8205가 saruparib가
됐습니다. 계열어 가드의 INN 예외가 맨 단어 `mab`에만 걸려 `pembrolizumab antibody`는 막고
`mab inhibitor`는 통과시켰습니다. 하나하나에 `tests/test_audit_round2.py` 회귀 시험이 있습니다.

### 1차

**골드 라벨 5건이 틀렸고, 전부 관대한 방향이었습니다.** `Abraxane`과 `Nab-Paclitaxel`을
PACLITAXEL로, `Bevacizumab Biosimilar HLX04`와 `Bevacizumab-Pfizer`를 BEVACIZUMAB으로 맞다고
채점했습니다. `Interferon-a`는 별칭이 `ifn`·`pegasys`·`pegylated interferon`인 ChEMBL 계열
노드에 매칭됐는데 맞다고 처리했고 — 같은 채점자가 세 행 앞에서 `Epothilone`에 대해 똑같은
오류를 **틀렸다**고 판정했습니다. 정정 내역과 사유는 `src/apply_label_corrections.py`에 있으며,
CSV를 직접 고치지 않고 스크립트로 적용해서 공표 수치가 어떤 라벨에서 나왔는지 추적됩니다.

**부당한 파생 관계를 삭제했습니다.** 이전에는 회사가 어떤 약물의 시험을 주도하면 `DEVELOPS`
엣지를 만들었습니다. 측정해보니 그 엣지의 **58.8%가 비산업 스폰서**였습니다. 그래프가
*국립암연구소가 파클리탁셀을 개발한다*, *메모리얼 슬론 케터링이 시스플라틴을 개발한다*,
그리고 개인 연구자가 주도한 시험 36건 때문에 *특정 의사가 니볼루맙을 개발한다*고 주장하고
있었습니다. 시험 주도는 관찰이고 약물 개발은 다른 주장이며, 이 소스들은 후자를 뒷받침하지
않습니다. 엣지 이름을 `SPONSORS_TRIAL_OF`로 바꾸고 스폰서 분류를 함께 실었으며, 개발 주장은
하지 않습니다.

**이 문서의 숫자가 산출물과 달랐습니다.** 노드 수를 6,481로 적었지만 모든 산출물은 6,475였고,
`class_term_as_synonym`을 56으로 적었지만 품질 리포트는 134였고, 커버리지를 78.3%로 적었지만
평가기는 78.2%를 출력했습니다. "2,008 → 66"이라는 큐레이션 수치는 **어떤 것으로도 재현되지
않았습니다.** 지금은 측정값입니다 — `src/curation_effect.py`가 전체 코퍼스를 큐레이션 전후로
두 번 해석해 `reports/curation_effect.json`에 기록합니다.

**근거 검증이 기본 경로에서 실패할 수 없었습니다.** 템플릿 답변은 검색된 근거를 이어붙여
만들어지므로, 그 근거와 대조하는 것은 순환논리이고 구조상 항상 통과합니다. 이제 생성이 아니라
렌더링된 답변에 대해서는 `applicable: false`를 반환하고 아무것도 주장하지 않습니다. 숫자 검사도
부분문자열 방식이어서 조작된 "47% 반응률"이 `47`을 포함한 NCT 번호에 통과했는데, 토큰 단위로
바꿨습니다 — 그리고 2차 감사가 그 토큰화가 소수를 깨뜨린다는 것을 찾았습니다.

**죽은 코드 한 줄(`break_outer = False`) 때문에** 회사명 정제가 문자열 중간의 업종어까지
제거하고 있었습니다. `Alliance For Clinical Trials In Oncology`가
`Alliance For Clinical Trials In`이 되고, `Spanish Lung Cancer Group`이
`Spanish Lung Cancer`가 되었습니다. 이제 법인격 표기는 어디서든 제거하되 업종어는 말미에서만,
그리고 학술·협력연구그룹 표지가 있는 이름에서는 아예 제거하지 않습니다.

**모회사 지도가 낡았고, 제약 업계 사람이라면 즉시 알아챌 오류가 하나 있었습니다.** Sandoz를
분사 3년 뒤까지 Novartis 자회사로 두었고, BeiGene의 2025년 신규 사명 BeOne Medicines를 반영하지
않아 한 회사가 두 노드로 존재했고, Seagen·Mirati·Turning Point·RayzeBio·Acerta·Alexion이
전부 미연결이었습니다. 그리고 **Merck KGaA 항목이 하나도 없는 채 Merck & Co만 다섯 개** 있었기
때문에, 다름슈타트 회사의 북미 법인인 EMD Serono가 떠 있는 동안 경쟁사만 온전히 매핑돼
있었습니다. 1차에서 항목을 채웠지만, 2차가 매칭 규칙이 여전히 두 Merck를 합치고 BeiGene 수정이
사명 변경을 소유 관계로 저장했다는 것을 찾았습니다(위 2차 참고).

**대시보드가 비결정적이었고 내용도 낡아 있었습니다.** Python `set`을 직렬화해서 재빌드마다
바이트 순서가 달라져 작업트리를 더럽혔고, 커밋된 사본은 `reports/`와 다른 실행에서 나온
것이었습니다 — 페이지를 연 사람과 JSON을 읽은 사람이 다른 숫자를 봤다는 뜻입니다.

## 이 파이프라인이 "하지 않는" 것

엔지니어링의 대부분은 거절 규칙입니다. 모두 가정이 아니라 데이터에서 실제로 발견한 오류입니다.

**위약 arm은 무투여 arm도, 투여 근거도 아닙니다.** `placebo plus docetaxel`에서는 도세탁셀이
실제로 투여됐고, `Placebo to Match ZD6474`에서는 아무것도 투여되지 않았습니다. 문자열 전체를
차단하면 후자는 안전하지만 전자에서 **참인 투여 기록이 조용히 사라집니다.**

**개발코드에는 퍼지 매칭을 쓰지 않습니다.** `BMS-986504`가 인접 BMS 코드와 유사도 88.9를
기록했습니다. 한 글자 차이가 다른 분자인 영역에서는 문자열 유사도 직관 자체가 틀렸습니다.

**숫자가 다르면 퍼지 매칭을 거부합니다.** `recombinant interleukin-12`가 `aldesleukin`(IL-2)과
97.9로 매칭됐습니다. 이제 숫자 토큰이 하나라도 다르면 매칭을 무효화합니다.

**부분 파싱은 미파싱보다 나쁩니다.** 구분자 없이 6개 물질을 나열한 문자열에서 첫 번째만 잡고
나머지를 버리면 **완전해 보이는 불완전한 레코드**가 생기고, 하류 어디서도 이를 탐지할 수
없습니다. 사전 기반 최장일치 분절로 찾을 수 있는 성분을 추출하고, 다섯 글자 이상이거나 개발코드 모양인 잔여물은 명시적 미해결로 방출합니다.

**바이오시밀러는 오리지네이터가 아닙니다.** `Bevacizumab Biosimilar HLX04`와
`Bevacizumab-Pfizer`는 별개의 허가 제품입니다. BEVACIZUMAB으로 해석하면 경쟁사의 자산을
제넨텍 분자 위에 올리고, 정작 연구 대상 자산은 사라집니다. 어휘에 식별자가 없으므로 사유
코드와 함께 거절합니다. 리포솜·알부민결합·나노입자 재제형, `Mvasi`·`Zirabev` 같은 바이오시밀러
상품명, 바이오시밀러에 붙는 것으로 알려진 FDA 접미사(`bevacizumab-awwb`)에도 같은 규칙이 적용되고,
오리지널 자신의 접미사(`cemiplimab-rwlc`)는 떼고 해석합니다. 정리하기 전 원문으로 검사하므로
병용 문자열이나 괄호 안에 적힌 재제형도 보입니다.

**부정된 약은 투여가 아니라 부재입니다.** `No pembrolizumab`은 그 arm이 받지 *않았다*는 기록이라
`EVALUATES` 엣지 대신 별도 계층 `BLOCKED_NEGATED`가 됩니다. 접두어는 부정이 아니어서
`Non-platinum chemotherapy: paclitaxel`의 파클리탁셀은 그대로 해석됩니다.

**계열어·유전자 심볼·동위원소는 약물이 아닙니다.** `PD-1 inhibitor`, `EGFR`, `18F`에 더해
`VEGF inhibitor`, `ALK inhibitor`, `CAR-T cells`, `antibody-drug conjugate`, 그리고 단독
`platinum`까지 가드가 붙었습니다. 독립 검토가 이들이 가드 없이 UNRESOLVED로 빠지거나,
platinum의 경우 7건의 시험에서 **신뢰도 1.00으로 화학 원소에 연결되고 있었다**는 것을
찾아냈습니다. 목록 완전성은 원리적으로 달성 불가능하므로, `inhibitor`·`blockade` 같은 핵어 앞에
유전자나 경로 수식어가 붙은 패턴을 규칙으로 잡습니다.

## 참조 데이터베이스도 틀립니다

이 스냅샷의 **atezolizumab** 동의어 목록에는 `avelumab`, `durvalumab`, `adebrelimab`,
`medi4736`이 들어 있습니다 — MEDI4736은 durvalumab의 개발코드이므로 다른 세 분자이고 그중 하나가
두 번 나옵니다. durvalumab 쪽에는 `atezolizumab`, `toripalimab`, 그리고 `durvalumab placebo`까지
있습니다. 그래서 어떤 레코드도 매칭하기 전에 사전을 먼저 큐레이션합니다. 수치는
`reports/quality_report.json`이고, 등록부 규칙이 먼저 돌기 때문에 아래 행들은 그 뒤에 남은 것을
셉니다.

| 결함 | 탐지 | 규칙 |
| --- | --- | --- |
| `registry_alias_removed` | 248 | 다른 성분(dexamethasone 아래 `tobramycin`)·요법(`CHOP`, `AC`)·여러 분자에 걸리는 약어(`lv`, `ici`)·별도 제품을 가리키는 AACT 동의어 제거 |
| `distinct_product_alias` | 204 | 바이오시밀러·재제형 이름(`abraxane`, `doxil`, `mvasi`, `bevacizumab-awwb`)을 출처와 무관하게 색인 전 제거 |
| `class_term_as_synonym` | 118 | `anti-PD-L1`, `pd-l1 blockade` 등 계열어를 색인에서 제거 |
| `genuinely_ambiguous_alias` | 99 | 모호성 유지, 해당 레코드는 검토로 |
| `parent_child_collapse` | 60 | 염·자식 형태를 모분자로 통합 |
| `cross_drug_synonym` | 57 | 다른 분자의 **정식명**인 별칭은 그 분자에 귀속; 나머지는 상류 오류로 기록 |

**1,997 → 4,053**으로 바뀝니다 (`reports/curation_effect.json`).

## 지식그래프

`Company` · `Investigator` · `Drug` · `Target` · `Disease` · `Trial` 살아 있는 노드 6,469개,
활성 엣지 17,564개.

| 관계 | 엣지 수 |
| --- | --- |
| `SPONSORS` | 4,652 |
| `EVALUATES` | 4,437 |
| `SPONSORS_TRIAL_OF` *(파생)* | 3,176 |
| `STUDIES` | 2,774 |
| `ACTS_ON` | 2,186 |
| `ASSOCIATED_WITH` | 300 |
| `PARENT_OF` | 39 |

모든 엣지가 **출처 · 수집 시각 · 신뢰도**를 보유합니다. 레코드 하나에서 읽은 엣지는 그 **원본
레코드**를 갖고, 파생 `SPONSORS_TRIAL_OF`는 레코드 하나가 아니라 여러 시험에서 나오므로 원본 레코드
칸이 비어 있는 대신 근거 시험 전체 목록을 속성에 싣습니다(3,176건 모두, 설계상). **해석 계층**은
자유 텍스트를 해석해 만든 엣지(`EVALUATES`, `STUDIES`)에만 있고 나머지 10,353건에는 없습니다.
수용된 해석만 엣지가 되고, 모호·차단·미해결 성분은 품질 리포트에만 남습니다.
그래프는 "참이라고 주장하는 부분"이기 때문입니다.

유일한 파생 관계는 근거가 보여주는 것만 말합니다. 3,176건 중 41.2%가 산업 스폰서이고 58.8%는
아니며, 분류가 엣지에 실려 있어 소비자가 필터링할 수 있습니다. 신뢰도는 "스폰서십이 기록돼 있다"는
뜻의 고정값 1.0이지, 시험 건수로 만든 점수가 아닙니다.

새 스냅샷으로 재구축해도 엣지와 노드를 삭제하지 않고 **은퇴(retire)**시키며 엣지 변경을 전부
변경 로그에 기록합니다. 같은 스냅샷으로 연달아 두 번 재구축하면 추가·변경·은퇴가 0건이고, 소스가
바뀌면 바뀐 만큼만 기록됩니다 — 파생 엣지는 기본 엣지를 정리한 뒤에 다시 계산합니다.

## 남아 있는 결함

조용히 덮는 대신 목록으로 남깁니다. 2차 때 여기서 `adenovirus` 백신 항목을 "더 재현되지 않는다"며
뺐는데, 3차 감사가 샘플의 더 긴 문자열에서 여전히 재현된다는 것을 보였습니다. 지금은 고쳤고 그
번호는 다른 항목에 다시 썼습니다.

1. **위약 규칙에 구분자가 필요합니다.** `Placebo Drug: Docetaxel Drug: Carboplatin`은
   `+`나 `and`가 없어 기준 arm으로 읽히고, 실제 투여된 두 약물이 누락됩니다.
2. **요법 약어가 펼쳐지지 않습니다.** 2차에서 요법 약어가 구성 약 하나로 해석되는 것은 막았지만
   (`CHOP`이 더는 prednisone이 되지 않음), `HS-20117+FOLFIRI`, `+mFOLFOX6`에서
   5-FU·류코보린·이리노테칸·옥살리플라틴·카페시타빈은 여전히 버려집니다.
3. **수리된 파이프라인에는 홀드아웃 측정이 없습니다.** 테스트 샘플은 세 차례 감사에 쓰였고,
   172행 중 26행이 낡은 라벨이며 오류는 전부 그쪽에 있었으므로 남은 98/98은 추정치가 아닙니다.
   개발셋(33행)과 수정 후 샘플(5행)도 같은 처지입니다. 현재 파이프라인에 숫자를 붙이는 유일한
   방법은 새 샘플, 가능하면 두 번째 채점자가 라벨링한 샘플입니다.
4. **커버리지 한계는 실력이 아니라 범위입니다.** 어휘가 NSCLC 연관 약물로 한정돼 `propranolol`은
   올바르게 거절되지만 커버리지에는 손해로 잡힙니다.
5. **여전히 채점자 1명, 독립 재채점 3회.** 1차는 62행을 재채점해 5건, 2차는 홀드아웃 58행에서
   2건과 수정 후 샘플 1건, 3차는 어려운 행 47개에서 4건이 불일치했고, 12건 모두 작성자가 관대했던
   쪽이었습니다. 일부러 어려운 행을 골랐으므로 불일치율은 아닙니다.
6. **네 계층은 독립 검증되지 않았습니다.** `CLEANED`, `SALT_STRIPPED`, `FUZZY_AUTO`,
   `FUZZY_REVIEW`는 고유값이 적어 개발셋이 전부 소진했고, 평가 JSON에 `carried`로 표시됩니다.
   층화 가중치의 0.9%입니다(`carried_tiers_weight_share`).
7. **수정 후 샘플은 수리를 확인해 주지 않습니다.** 구간이 너무 넓고 같은 채점자 1명이 채점했습니다.
   수리가 유지된다는 근거는 이 샘플이 아니라 회귀 시험입니다.
8. **질의층이 가장 가까운 질문에 답합니다.** "펨브롤리주맙이 자가면역질환 환자에게 안전한가?"는
   거절되지 않고 약물 프로파일이 반환됩니다. 엔티티가 전혀 연결되지 않을 때만 거절합니다.
9. **`MEDI4736`이 모호로 남습니다.** 실제로는 durvalumab이 확실하지만 오염된 동의어가 정식명
   규칙을 막습니다.
10. **두 단어 인명과 짧은 회사명은 구분되지 않습니다.** `Xiuning Le`는 사람이고
    `Shanghai Henlius`는 회사인데, 문자열만으로는 나눌 수 없습니다. 명시적 학위 표기(`MD`,
    `PhD`)만 사용하므로 `Investigator` 노드 36개는 학위가 적힌 것들이고 나머지는 `Company`로
    남습니다. 모양으로 추측하던 이전 판은 Accuray와 Daiichi Sankyo를 사람으로 분류했습니다.
11. **등록부 동의어 규칙은 거절 쪽으로 틀립니다.** 오염된 동의어와 함께 맞는 이름도 일부 지웁니다 —
    다른 성분과 구분 못 하는 오탈자(`terelizumab` = tislelizumab, `slulimumab` = serplulimab),
    분자 레코드에 없는 코드명(`limertinib` = ASK-120067, `pankomab-gex` = gatipotuzumab,
    disitamab vedotin 아래 변형 4개), 어휘 전체에서 모호한 짧은 약어(`epi`, `hr3`, `il-2`).
    제거마다 사유와 함께 품질 리포트에 남으므로 검토할 수 있습니다.
12. **모회사 지도는 날짜가 붙은 주장입니다.** 모회사 키 56개와 같은 회사 키 8개를 분사·사명 변경·두 Merck 같은 뚜렷한
    변화에 대해 확인했지만, 모든 자회사의 법인 존속은 검증하지 않았고 소유가 바뀌어도 다시 확인하는
    장치가 없습니다.
13. **주장 검사는 뜻이 아니라 단어 순서를 읽습니다.** 생성된 답을 절마다 주어·관계·목적어로 읽어
    (`src/claims.py`, 규칙은 docstring) 그 대상들의 근거와 대조합니다. 정해진 문장 모양을 읽는 규칙이라
    처음 보는 모양에는 약합니다. 적대 검증 다섯 차례에서 33개, 약 40개, 약 25개, 약 20개, 약 15개의 빠져나가는 모양(뒤집힌
    명사형, 강조 구문, "and on" 뒤 두 번째 대상, 너무 일찍 풀린 대명사, 복수 대명사, 단계 숫자나 다른 약의
    숫자를 시험 수로 빌림, antagonist 안의 agonist, 목록 제목, 대괄호 글, 거절된 제품 이름, "clinical
    trials"·"drug"를 문법 단어로 취급, "approved in NSCLC", "the following safe drugs", 두 시험이 나눈
    단계·상태, 한 글자씩 띄워 쓴 단어, 제목·관계절 속 종류 단어, "10 such trials")이 나왔고 모두 회귀 시험이 됐지만, 아직 아무도
    시도하지 않은 모양은 잘못 읽을 수 있습니다. 알려진 통과: 한 대상에 대한 근거 문장 하나의 단어·대상·숫자로
    다른 주장을 짜 맞춘 절, 어휘에 없고 INN 모양도 아닌 약 이름, 근거와 어긋나지 않는 어색한 표현("osimertinib
    is the inhibition of EGFR"). 알려진 과잉 차단: 그래프에 없는 참인 사실, 단어가 없는 바꿔 말하기
    ("supports trials"), 근거 자체를 설명하며 부정·"develops"를 쓴 문장, 그래프 밖 대상을 말하는 거절 문장
    ("the capital of France"). 일부러 둔 예외 세 가지: 근거 문장을 옮긴 줄(그 위 제목은 검사), 대상 없이
    그래프 자체만 말하는 절, 안의 식별자가 모두 검색된 근거의 기록일 때만 지우는 대괄호 인용.
14. **출처 기록에 코드 버전이 없습니다.** 스냅샷은 수집 시각을 갖지만 그래프는 어떤 규칙 버전이
    만들었는지 저장하지 않으므로, 새 스냅샷과 코드 변경이 함께 들어오면 데이터베이스만으로는
    둘을 나눌 수 없고 git 이력으로만 가능합니다.

## 실행

```bash
pip install -r requirements.txt

python src/run_all.py              # 수집 → 해석 → 검증 → 그래프 → 채점 → 렌더
python src/run_all.py --offline    # data/raw 스냅샷으로 재현

python -m pytest tests -q          # 275개 테스트
python src/app.py                  # 직접 써 보기 화면: http://localhost:8765
python src/apply_label_corrections.py --check
python src/curation_effect.py      # 큐레이션 전후 두 번 해석
python src/query.py "Which companies are developing osimertinib?"
```

수집이 조용히 일어나지는 않습니다. `data/raw/*.json`이 수집 스냅샷이고 각각 질의 내용과 수집 시각이
찍혀 있습니다. 이후 단계는 이 파일과 서로의 산출물(`resolved.json`, SQLite 그래프, 골드 CSV)을 읽습니다.
소스 변경과 로직 변경을 가르는 것은 git의 몫이고, 산출물은 어떤 코드 버전이 만들었는지 기록하지
않습니다.
